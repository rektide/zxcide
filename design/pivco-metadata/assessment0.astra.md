# Test the lifetime of the PivCo breadth-first queue first

**Build one candidate: lend the decoder an empty worker-local `VecDeque` and keep its allocation after a successful Huffman section only if it holds at most 16 entries.** The FIFO already contains only integers. This tests the site responsible for 768 of 1,024 traversal allocation/growth events on 4 KiB mixed, without changing a single bitmap address or merge record. The retention budget is 384 bytes of elements per 64-bit worker. Whether this saves meaningful decode time is open; this assessment uses existing counts and source inspection, no new machine timings.

## What the proposed change can buy

Use Rust `3db98c67065f6bb6d49c88a1fae83ccd05efcee1` as the reference, **with** [worker byte-buffer reuse](../../doc/profiling/pivco-worker.md). In [`Tree::decode_into`](../../crates/codec/src/entropy.rs) the order Vec gets one allocation sized to *all tree nodes*, even for a perfect tree whose root unpacks directly. A separate FIFO starts with the root and grows as it queues `(node, start, count)` in left/right wire order. The diagnostic counted `2 + queue_growth` per successful section: one initial order allocation, one initial FIFO allocation, plus increases in FIFO capacity. Subtract sections from traversal events in the [serial trial rows](../../doc/profiling/pivco-worker-data/allocations.tsv):

| Fixed input | Order events | FIFO events | Why include it |
| --- | ---: | ---: | --- |
| 4 KiB Dense mixed (1 MiB plaintext) | 256 | 768 | Many opportunities per decoded byte; primary target |
| Dense / C7 `sao` | 28 / 20 | 84 / 50 | Large runs; allocator savings must compete with gather and LZ |
| Dense / C7 full Silesia | 813 / 797 | 2,775 / 1,964 | Different tables, frequencies and frame-local pool lifetimes |
| 4 KiB sparse entropy / all RAW | 1 / 0 | 3 / 0 | Little or no opportunity to amortize retention |

These are capacity events at two sites, not all allocator calls, bytes or cycles. In the saved serial `diag-*-w1-trial.log.gz` traces, the maximum additional FIFO growth count (`S` record's `meta` minus two) was two on 4 KiB mixed and Dense `sao`, three on either full corpus. This motivates a **small retention cap**, not a 16-entry format limit. Measure actual capacities before attributing anything to the cap.

### What to borrow from pinned C

The [C tree](https://github.com/hellobertrand/zxc/blob/5719a96f778226868b29dba621a8c4e302b74d7c/src/lib/zxc_internal.h#L804-L851) stores leaves then internal nodes at each depth; two children of internal position `k` are at `2k, 2k+1` in the next level. The [builder](https://github.com/hellobertrand/zxc/blob/5719a96f778226868b29dba621a8c4e302b74d7c/src/lib/zxc_huffman.c#L1048-L1126) orders flat leaves by packed code. The [decode core and its two callers](https://github.com/hellobertrand/zxc/blob/5719a96f778226868b29dba621a8c4e302b74d7c/src/lib/zxc_huffman.c#L2176-L2322) need only `uint32_t count[512]` (includes a missing-child slot) and 11 run-start pointers: 2,136 bytes on LP64 or 2,092 with 32-bit pointers, excluding tree, locals and symbol buffers. These arrays are per call, not a worker cache. A second pass recovers starts with level cursors and alternates destination/scratch by depth. The dictionary supplies the immutable prebuilt tree.

Rust's node indices follow **construction** order, not C's dense levels. Rust fills leaves and flat subtrees during discovery, saves `(start, n, ones, &[u8])` for non-flat internal nodes, then runs the saved list in reverse, skipping uniform merges. C's bounded metadata is evidence for sizing from the alphabet, not a drop-in queue or an equivalence oracle for malformed sections: its core rejects `n == 0` and does not test `p == pend` after the sizing walk. Rust accepts count zero with an empty run payload and requires exact exhaustion even then. Keep both Rust behaviors. A [previous layout experiment](../../doc/profiling/pivco-scratch.md) removed copy-back but regressed whole-call 4 KiB WIT; do not include that change here.

## First candidate: queue lifetime only

1. In [`Sections`](../../crates/codec/src/block.rs) add one initially empty private queue, shared sequentially by Huffman literals and tokens, never stored on `Tree` or `Dictionary`. Pass it through the two Huffman arms of `section`. The returned prefix borrows the output Vec only; neither the queue nor the merge scratch is borrowed by the returned slice. RAW/RLE need no queue preparation. Keep the test convenience wrapper supplying fresh scratch.
2. At Huffman entry take the queue out (`mem::take`). On cold use construct the same singleton-root queue as today; on warm use push `(0,0,count)` into the empty queue. Run the existing `pop_front`/`push_back`, including zero-count children, exactly as written. Keep the existing order Vec, slices, popcount, flat unpack, uniform skip, gather and copy-back. On success, return the **drained** queue to the worker only when `capacity() <= 16`; otherwise let the local drop. On any early `?` the local drops, even with pending nodes; no clear-on-every-exit scheme or lifetime cast. A later LZ/checksum failure can leave an *empty*, already returned queue. Test both cases.
3. The cap limits **retention**, not admission: valid larger frontiers grow normally and remain decodable. Every queued node denotes a disjoint subtree of a tree with at most 256 leaves; even a zero-population subtree owns at least one alphabet leaf. Thus at most 256 live FIFO records (including the unary exception), each three machine words. This is a logical bound, not a promise about `VecDeque`'s spare capacity. Measure actual transient capacity. No input-sized allocation, stack slab, new dependency or unsafe code is needed for this change.

**Budget.** With `W = size_of::<usize>()`, additional retained element capacity is at most `16 × 3W`: 384 B native64, 192 B wasm32; at four active 64-bit workers, 1,536 B plus four queue headers. Verify `size_of::<BlockDecoder>()` delta and record the inline overhead even for RAW-only workers. Don't count capacity twice while the worker lends the queue to a section. The byte-buffer bound remains `2B + floor(B/5)` for frame limit `B`; at 4 KiB it is 9,011 B before this queue, up to 9,395 B after on native64. Neither bound is RSS. On the first smaller RAW block, oversized byte buffers still drop; an empty FIFO may retain its ≤384 B regardless of frame size. A fresh RAW-only worker allocates zero queue bytes. Serial survives calls/frames, Crossbeam workers end with the frame, WIT creates a decoder per call. Report end-of-block, end-of-frame-before-drop and concurrent worker bounds separately.

## Other bounded designs and what they would test

For a validated complete tree with `L ≤ 256` leaves there are `2L−1 ≤ 511` nodes and at most 255 internal nodes; the special one-symbol tree has two nodes, one internal. Flat subtrees reduce actual visits. The [wire and block checks](../../crates/codec/src/wire.rs) bound payload length and section counts by `B ≤ 2²¹`; symbol counts and byte offsets need more than 16 bits even though node IDs do not.

| Single-variable alternative | Cost and decision |
| --- | --- |
| Trim the local order reserve only | Existing entry is five words (40/20 B on native64/wasm32). Reserving at most the internal-node count instead of whole-tree count cuts the maximum **requested** reservation from 20,440 to 10,200 B on native64 (10,220 to 5,100 B on wasm32). Still one allocation even for a flat root. Easy separate capacity experiment if over-reservation, rather than allocation frequency, matters. |
| Compact order records, **still local** | Four `u32` fields `start,n,ones,run_byte_offset` = 16 B per slot on both targets. With unchanged 511-slot reserve: 8,176 B; with a *separate later* 255-slot cap: 4,080 B. Keep an immutable `payload` and record `payload.len() − remaining.len()` just before the checked `take`; only record after it succeeds. During reverse merge use the exact `payload[offset..offset+ceil(n/8)]` (checked range, valid for this non-flat record only). Keep order of reads/errors and `require(remaining.is_empty())`; never use the whole suffix as a bitmap. Document checked conversions or prove each from validated callers, including 32-bit arithmetic. Only after testing the representation alone could an owned, capped Vec be reused across sections; no input slices, pointers or tree IDs survive. |
| Fixed arrays or a single append-only BFS Vec with a head cursor | Avoids a deque or ring growth but changes initialization and bytes touched. Reserving all 511 visits at three words costs 12,264/6,132 B, even when the active frontier is tiny. An inline 16-slot FIFO costs 384/192 B even for cold workers and needs a correct spill path; 16 is not a checked bound on valid wire. Measure a fresh local design independently if cold allocation dominates. |
| Port C's level metadata | Small count table, no per-run slice. Requires either deriving depth/position→Rust node mapping or changing `Tree` (also used by the [encoder](../../crates/codec/src/entropy/pack.rs) and dictionary). A different tree build, traversal and merge placement in one diff would not identify the cause of a win. Defer until evidence singles out discovery or order replay. |

If queue reuse is neutral, the experiment still distinguishes repeated allocation cost from excessive *order capacity*. Don't combine losers, narrow integers in the FIFO, filter uniform records, cache inline tables, or change code generation flags to clear the gate.

## Validation before timing

- Keep Rust's 128-byte table, maximum length 11, exact Kraft sum or lone length-1 exception; retain LSB-first flat mapping at widths 1–8, byte-ceiling per nonempty run and masked unused tail bits. For an interval `[s,s+n)` the children partition it at `s+n−ones`; a missing child is legal only for population zero. Zero-population nodes consume no run. Keep exact exhaustion before replay; leaves/flat nodes initialize every logical byte, and uniform nodes can skip gathering without skipping discovery of their populated descendant.
- Run the [entropy tests](../../crates/codec/src/entropy/tests.rs) and extend the [worker reuse test](../../crates/codec/src/block/tests.rs): decode a mixed multi-level tree, stop **inside** a short run with a sibling still queued (valid outer body length), and reuse the same worker on a shorter valid *different* tree/input. Also test a trailing run byte, a singleton selecting a missing child, and valid zero-count versus trailing-byte zero-count. Check exact decoded prefixes and failure classes against baseline. Exercise the oversized-cache discard rule via a deliberately over-capacity drained queue in a focused test if real fixtures never spill.
- Decode multiple blocks sharing one dictionary (confirm literal encoding **3**, not just the dictionary flag), also inline token mode 2 in that worker; use a different dictionary/tree next. Check wrong/missing dictionary, dictionary-to-output crossings and exact `decode_owned` publication. Cover RAW downshift then small entropy, late checksum/limit failure then valid input; failed data block never published, earlier verified stream blocks may already be written. No shared mutable dictionary or stale records on any return path.
- Use locked workspace nextest with `--features zxc-cli/transports`, scalar release codec tests, codec Clippy with `merge-simd,ledger` and denied warnings, and validate the default scalar component. Run `cargo xtask interop <pinned-C> <candidate-Rust> --cases 36`, then the Crossbeam generated run (`--parallel-backend crossbeam`). Require frozen/generated cross-decodes and indexed ranges as in the [previous verification](../../doc/profiling/pivco-worker-data/verification.txt); keep checksum, max-output, grouping/order and footer/EOF checks. Baseline Rust is the rejection oracle; C cross-decodes establish valid-wire interoperability.

## Measurement and decision for Sol high

**Start with an untimed attribution run.** On both revisions separate cold FIFO allocation, FIFO growth, cache reuse, discarded capacity, max logical frontier, order length/capacity and its one allocation; split by inline vs dictionary, literal vs token, worker and frame. Record section count, flat symbols, mixed gathered/returned bytes, byte-buffer growth/zeroing, metadata peak and retained bytes (per worker; distinguish allocator overhead). Inline `Tree::new` has its own builder queue, node allocations and flat lookup Vecs: neither charge them to the decode FIFO nor claim to remove them. Update the ledger's existing auxiliary-capacity calculation if needed so it counts the loaned queue exactly once. Dense `sao` must still have 28 sections, 4,542,662 flat symbols and 15,059,269 B **each** gathered and copied back. The warmed 4 KiB mixed serial run should show no FIFO growth on repeated fitting shapes and ≥90% fewer FIFO events overall; if not, explain the miss before timing. Trace the existing Dense `sao` → RAW 4 KiB → Dense mixed 4 KiB downshift, cold RAW, and dictionary/error reuse. Report both the three byte Vecs and the queue, including capacity on errors.

**Then compare clean binaries on fixed archives.** Reuse the [worker protocol and fixture definitions](../../doc/profiling/pivco-worker.md#fixed-archive-timing) and [SHA-256 identities](../../doc/profiling/pivco-worker-data/sha256.txt). Freeze new locked Release baseline and trial from clean source exports with identical CLI `merge-simd` defaults and toolchain, no ledger/Tracy/debug counters or native tuning. One fixture set for both decoders: no candidate re-encoding. Save commands, revisions, features, host/affinity, binary/component/fixture/plain hashes and raw samples. Check exact plaintext through EOF before timing at each worker setting; require successful quiet exit every timed run. Use adjacent balanced/shuffled A/B pairs, warmup then **two independent 12-pair series**; report each median of pairwise wall and child CPU deltas (raw samples or paired intervals too).

**Keep/drop rule (set before build).** Keep only if correctness and memory bounds pass, the ≥90% FIFO-event reduction is observed, and the primary serial 4 KiB mixed archive takes **≥5% less wall time in both series**, corroborated by lower child CPU in both. Record Dense and C7 `sao` and both full corpora regardless of the primary timing result; do not generalize a small-block win to them. No reproducible >3% regression on native controls, dictionary, full corpus, or default WIT (particularly 4 KiB mixed). For a marginal/noisy control that could affect promotion, repeat two balanced 24-pair series, using longer single-frame controls for launch-dominated cases; report inconclusive if still unresolved. No parallel scaling claim from child CPU alone. If allocation counts improve but time does not, **drop the default code**, retain the diagnostic result, and use measured order capacity/occupancy to decide whether a separate local order-size experiment is worth running.
