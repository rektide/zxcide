# Comparing checked decode stages with Tracy

**Build a small local C fork. Share a definition of work, not a tracing library between languages.** The question is whether materializing literal/token sections and reconstructing output take longer on the *same checked SPL16 blocks* in the file CLI, and whether that changes with parallel delivery. Capture each implementation separately. The clean comparison running independently is the authority for wall throughput and child CPU. It does not need this fork.

The [pool experiment](../../doc/profiling/decode-pool.md) changed 96 worker starts to eight on the 12-frame bundle; it hardly changed single-frame CPU. The [replay](../../doc/profiling/decode-replay0.sol.md) removed both file drivers and found C used 39–40% less **replay-thread CPU** on the long frame. Separate stage clocks found Rust − C about +0.16 **elapsed** s/GB preparing sections, +0.10 reconstructing and little difference hashing. Replay had one reused output block, no ordered write, and a different cache regime. Those are reasons to instrument the real checked CLI path, not predictions of the multi-worker split. This wave specifies an experiment; it reports no new timings.

## What already works in Rust

At the Rust revision above, [the smoke task](../../xtask/src/smoke.rs) builds `--locked --profile profiling -p zxc-cli --features tracy` (release inheritance, debug=1, no stripping). It repeats `valid/spl_pivco_wide_l7.zxc` 1,000 times by default, starts `zxc --wait-for-tracy test repeated.zxc` with `TRACY_PORT` (default 18086), and captures at `127.0.0.1`. The [CLI](../../crates/cli/src/main.rs) holds `Client::start()` across the command and polls connection every 10 ms, timing out at 30 s. The task bounds child waits at 90 s and kills/reaps on failure. It checks status and a nonempty file; it neither verifies exported zones nor writes plaintext to OS stdout. **Keep this command and its fixture as a Rust smoke**, not the common benchmark.

`tracy` is opt-in, forwarded by the CLI to codec/parallel/seek; the CLI defaults to `merge-simd`. Codec/parallel use tiny `#[cfg(feature="tracy")]` static-span macros; seek uses direct spans. [Cargo.lock](../../Cargo.lock) resolves `tracy-client 0.19.0` and `tracy-client-sys 0.30.1`. The latter's packaged `tracy/common/TracyVersion.hpp` says **0.14.1** and `TracyProtocol.hpp` says **82**. Workspace dependency defaults are off; features `enable,ondemand,only-localhost`; `span!(name)` requests stack depth zero. The capture and csvexport binaries on this host's ordinary PATH identify as **0.15.0 / c7e1ead8**. The cached 0.14.1 pair under `~/.cache/opencode/tmp/zxc-tracy.jBOVlP/` identifies as `30997d5`; treat paths as hints, verify tools each time. Don't upgrade the Rust client to make a system binary work.

## Fork, builds and identities

1. Sol owns a **new independent local repo** at `~/src/zxc-decode-tracy/` (if occupied by unrelated work choose a fresh sibling and record it). Import the exact commit from `target/comparison-acceptance/comparison-report/cache/5719a96f778226868b29dba621a8c4e302b74d7c/source/`, or another verified clone containing it. For the shallow, detached cache, one recipe is `git init` in the new directory, `git fetch --depth=1 file://<absolute-source-dir> <full-pin>`, `git switch -c decode-tracy-v1 FETCH_HEAD`; verify base commit and tree. Full archive clone at that pin also works. Commit the C changes there. No worktree registration in the cache, no borrowed alternates, no build in the source tree, no public fork or push. Never repoint `PERF_REV`, `target/upstream-comparison/current`, the comparison builder, or the interop oracle.
2. Make the work reproducible after losing that local branch: track in zxc-rs `xtask/probes/decode-tracy/` the pin manifest, ordered `git format-patch --full-index` series from base to fork tip, bootstrap/build/capture/check recipes and boundary map. Include canonical upstream URL, base SHA/tree, original commit IDs, patch SHA-256s, expected patched **tree** (replaying commits can change committer metadata), Tracy/client/tools pins and licenses. Avoid a vendored copy of either repo, dirty-cache diffs, floating FetchContent, automatic fetch/latest or submodules in the release build. Prove a fresh checkout at the base applies the exact patches and yields that tree; fail closed on mismatch. Scratch, logs, binaries and private traces under `.test-agent/decode-tracy/<run-id>/`, no overwrites. Keep the measured baseline snapshots distinct.
3. C remains `project(... LANGUAGES C)` by default. Introduce one private option e.g. `ZXC_PROFILE_TRACY=OFF`. OFF preprocesses probes away (no evaluating arguments), configures offline without a Tracy path, C++ compiler, include, library, flags, startup or attach option. Build OFF in `c-off/` with [the reference recipe](../../xtask/comparison_build.py): Release, static, `-O3 -DNDEBUG`, `ZXC_NATIVE_ARCH=ON`, same compiler and variants. Build ON separately in `c-cap/`, same optimization/dispatch; record any debug-line/prefix-map flags. Enable CXX **only there**, use a verified local export of the Tracy pin; compile `public/TracyClient.cpp` **once** as a static C++ client with its required platform libs; C codec/driver/CLI remain C17. Use `public/tracy/TracyC.h` and a tiny private C header; no changes to public ABI/format. Do not use a system Tracy library. Check CMake cache, actual `compile_commands.json`, final link map/`nm` and dependencies; OFF has no Tracy symbols or client link (including static linkage).
4. Compile both the C-facing probes **and** the C++ client with `TRACY_ENABLE, TRACY_ON_DEMAND, TRACY_ONLY_LOCALHOST` consistently (`TracyCZoneCtx` layout depends on on-demand). Mirror locked sys `build.rs` choices: stack depth zero; `TRACY_NO_{BROADCAST,CODE_TRANSFER,SAMPLING,SYSTEM_TRACING,CONTEXT_SWITCH,WAIT_STACKS,CALLSTACK_INLINES,CRASH_HANDLER,VERIFY}`. Separate diagnostic build with zone verification enabled is fine for testing error unwinds; don't compare a debug client to a release one. No allocation events, symbol samples or context-switch collection in this capture.
5. `cmake/zxcVariants.cmake::zxc_add_variant` compiles **separate OBJECT targets** for compress/decompress/huffman. `zxc_lib` consumes `$<TARGET_OBJECTS:...>`; setting its private flags alone does not instrument those compilations. Supply private include/defines to *each instrumented* `zxc_decompress${suffix}`, and the instrumented driver/CLI as needed. Keep `_default`, `_avx2`, `_avx512` and their individual flags on x86; baseline may already use SSE2. AArch64 uses baseline NEON, ARMv7 may add `_neon32`. No source copies per ISA; don't force `_default` or run AVX512 on unsupported hardware. Check all compiled variants, one actually executed (`perf` on clean binaries separately or dispatch-symbol evidence). C's generic lib/CLI `-march=native` and dispatched kernels' explicit `-m…` flags are different decisions.
6. Give Rust its own scratch Cargo target(s). Compare OFF/ON at the same profile and rustflags (`--locked --profile profiling`, defaults intact, toggle only `tracy`); identify normal portable `--release` separately. Ordinary Rust CLI, WIT/component and downstream libraries acquire no default Tracy dependency. `cargo tree -e features -p zxc-cli` without vs with `--features tracy`, build/link receipts and default CLI behavior should demonstrate that. Record binary SHA-256s rather than assuming OFF equals an independently built binary byte for byte (paths/build IDs may differ).

Compare successful, no-dictionary, checked SPL16 file decodes only. IDs below are relative to `decode-tracy/v1`; use literal labels for new sites, alias existing labels at the named sites instead of changing every historical trace. Match every event on its own thread. A missing mapping is `unmapped`, never a duration of zero.

**Section preparation needs no additional probe.** For each successful `spl.payload`, require exactly one same-thread contained `spl.reconstruct`. Calculate `spl.prepare = reconstruct.start − payload.start` from that **pair of events**, not from aggregate medians. This measures the prefix up to usable sections, includes parsing/validation, RAW/RLE and both Huffman children where present. C's raw-token specialization parses descriptors then *returns the call to its entropy twin*, which reparses them (decompress.c:817–832). An entry zone in the common inline body would double-count or leave the first zone open. The outer call and single post-materialization marker count both parses once and require no context passed through specializations. Report the small tail after `reconstruct.end` separately if relevant. Never sum `prepare` with its Huffman children.

**Balance is a correctness requirement.** At the driver and SPL switch use explicit `TracyCZoneN`/`TracyCZoneEnd` around one evaluated call and close *before* error tests, `break` or `return`; similarly use inner lexical scopes for section calls, including when they fail. C17 braces alone do **not** close a Tracy span. For the reconstruct site alone a capture-only GCC/Clang lexical cleanup is justified on the Linux target: begin a named zone, have one initialized automatic guard owning its `TracyCZoneCtx`, cleanup emits exactly one end on leaving the scope. Never manually end that context also. All rollback labels/fast-safe loop jumps remain inside the scope; early direct and macro-expanded error returns unwind it. No `longjmp` or thread transfer in this path. Audit this again on rebase. Reject unsupported capture compilers at configure time rather than silently emitting unbalanced spans. OFF expands to nothing. An equally small implementation with proven single-exit pairing is acceptable; **do not** rewrite hot loops or change their inlining for tracing. If this scope can't be balanced, report the missing stage; don't use `payload minus Huffman` as LZ. Rust's existing lexical guards should stay in scope across `?` and drop on all exits.

### Explicitly unmapped

- Serial Rust `decode block` includes `frame.commit` and `write_all`; parallel `parallel worker compute` includes worker scratch/`decode_owned` handoff and is also used on encode. Neither is `block.checked`. Keep both as implementation-local context. `PivCo decode` starts **after** inline `Tree::new` and conflates section roles; retain as a Rust child rather than renaming it to whole-section decode. Same for `RLE decode`.
- Rust `read payload`, `write plaintext`, `decode frame`, `parallel decode frame`, Crossbeam send/recv/ordered head/commit and Rayon batch barrier answer local questions. C reads headers on the caller and may `pread` bodies on workers; jobs can batch blocks, writer `fwrite`s after unlocking and releases credit separately. C `-T1` still has worker + writer; Rust `--threads 1` is serial. Don't pair job with block, `write_all` with disk latency, or condvar sleep with channel wait. No zones across a lock handoff or across threads. Input mode, buffering, ordered publication, footer checks, operation/pool startup and teardown belong in the CLI description, not silently in a codec row.
- Seek/indexed ranges, encode/match finding/entropy pricing, buffer/push APIs, PAK/RAW reconstruction, dictionary, component and other transports have **no v1 comparison**. Native build coverage is not a claim about another ISA or the strict-tail path. Keep original static labels; if a boundary actually moves, change the map version. No common crate/FFI facade, generated bindings, dynamic block names, per-symbol logging, counters or Tracy flows in slice one.

## A capture that can fail usefully

Use one paired runner in the probe directory taking explicit `--c`, `--rust`, `--capture`, `--csvexport`, fixture manifest, port and new output directory. Keep it separate from the clean comparison runner. One implementation per process/trace, sequentially. Preflight both tool banners (capture usage with no args; csvexport `-h`), pin/hashes and protocol headers; report incompatible binaries **before** starting the workload. Same two verified tools for both sides. Never patch the protocol constant to pass a handshake.

The existing Rust wait flag is sufficient. C ON gets one opt-in environment switch, e.g. `ZXC_WAIT_FOR_TRACY=1` checked once in CLI startup **before opening/decoding files or launching codec threads**, with monotonic 30 s deadline, short sleeping poll on **`TracyCIsConnected`**, diagnostic to stderr and nonzero exit on timeout. No wait by default; nothing in a decoder library or OFF. Runner locks the experiment/port, confirms no existing listener, sets explicit `TRACY_PORT`, starts that client with ordinary file input, then matching `tracy-capture -a 127.0.0.1 -p PORT -o NEW.tracy`. No sleep-as-readiness, no dummy TCP connection (it can consume the session); a port being open isn't a completed Tracy connection. Observe both child statuses, cap total time (e.g. 90 s for this smoke), kill/reap both on any failure/interruption, keep partial logs marked failed. Check actual loopback binding and no discovery broadcast. Require exported expected event counts and containment after clean disconnect; a nonempty trace alone, or an attach to some other program, is not success.

**Use the [pool manifest](../../doc/profiling/decode-pool-data/fixture-manifest.json) and the same regular input file**, not “level 7” re-encoded by each side. Primary `single.zxc`: 70,139,019 archive bytes, SHA-256 `32608ad174575d9e7563bcc9f535a94ba32033480c34deb6d9cbe972c40f0843`; 405 SPL16 blocks, 211,938,580 plaintext bytes, SHA-256 `cc3b55db1901a40a0de1c6ad5a3fdd469c487b626a5359279d4e201a552bf45b`. A header-only census at the pinned fixture gives 405 inline token and 380 inline literal sections (21 raw, four RLE literals). Small functional fixture `sao.zxc`: 14 blocks, 14 token and **six** literal Huffman sections; member digests in manifest. `mozilla.zxc`: 98/98/87. Count the four non-role-specific IDs once per checked SPL block on these successes. These cardinalities catch wrong variants, duplicate tail-call zones and summaries that group both roles as “entropy”. `concat.zxc` has the same plaintext but **different archive bytes** (70,113,423; 12 frames); it is a later pool/layout control, not a substitute for `single.zxc`.

Use `C -qdc -T1 INPUT` and `RUST [--wait-for-tracy] decode --threads 1 INPUT`, both writing stdout. For W=8 use `-T8` / `--threads 8` (Rust default Crossbeam); record affinities, implementation topology, input type, slots and sink. Exact preflight per binary/input/worker combination, including connected path: check archive size/hash, consume stdout to EOF, require exit 0 and exact expected byte length + SHA-256 (or `cmp` to the bound plaintext), check stderr separately. Capture to a fresh regular stdout file and check it afterward, then use `/dev/null` on **both** for the null-sink comparison. Do not time hashing or an external pipe consumer. Neither Rust `test` → `io::sink()` nor C `-t` → null `FILE*` has the OS-output contract. Regular file means buffered writes, no `fsync` claim. On a private copy flip one bit of a stored block checksum; require checksum rejection in OFF and attached builds, same behavior as each stock CLI including ordered output prefix where applicable. Also exercise an existing invalid SPL reconstruction case with verification-enabled capture to test early return. Keep invalid traces separate from success denominators.

**Artifacts.** Save one manifest per run with schema/map version, C base/tree/patch series and Rust revision/dirty paths, tool and executable hashes/versions, features, CMake and Cargo commands, per-ISA flags, observed dispatch or `unknown`, CPU/OS/affinity/SMT, worker count, fixture/output digests/lengths, argv/sink, statuses, port and capture identity. Keep `.tracy` and `tracy-csvexport -u` event CSV for each client, alongside aggregate CSV for inspection. Parse quoted CSV by column name (`name,src_file,src_line,ns_since_start,exec_time_ns,thread,…`); resolve sites using revision + relative file, not absolute paths or a line number alone. Match parent/child intervals on the same lane, check schema counts and nesting before comparisons. Pair **by case/worker/sink/build flavor**, not by absolute timestamps, thread IDs or cross-process completion order. Compare per-stage count, inclusive elapsed sum/plaintext GB, distribution per block/section, decoded symbols from fixture census if needed. Label self time explicitly; Rust has additional nested zones. A given duration includes descheduling; sums over workers overlap, sums over parents and children overlap. No “% of CPU gap explained”, no inference of cycles from a trace. Use clean `wait4` child CPU/GB and wall, separately sampled clean `perf` and controlled replay for attribution.

Tracy can disclose source filenames, user/build paths, function names, binary/host metadata and timings even with code transfer off. Use non-sensitive fixtures, static roles only, private run directory (`umask 077`). No content, filenames from the input, dictionary bytes or dynamic text attached to events. Prefer stable relative source roots / C `-ffile-prefix-map`, Rust `--remap-path-prefix` in both matched profile flavors if needed; record flags and check the exported paths. Review/redact summaries and manifests before sharing; keep raw traces, symbols, logs and CSV local by default. Loopback limits the network audience; it is not authentication or anonymization.

## When a trace is fit for comparison

**Distinguish three costs within each implementation:** matched optimized OFF, ON disconnected (no wait), ON connected. Disconnected is not clean. Hold compiler/flags, I/O, worker count, CPU set and exact bytes fixed. Give the collector separate CPU affinity if available; report decoder child user+sys and capture-process resources separately. Lock `.test-agent/zxc-perf.lock`; do not run builds/captures/benchmarks against Sol xhigh's clean series. All speed claims come from clean repeated pairs.

Predeclare a gate before using phase magnitudes: two independently ordered series of at least 12 adjacent balanced pairs per claimed cell with OFF/OFF noise control, warm inputs, actual statuses and exactness. Measure **incremental work** for a connected process, not spawn-to-exit with 30 s attach wait versus an OFF decode. One no-code-change method: prepare short and long regular archives of N and 2N byte-identical consecutive copies of `single.zxc` (e.g. N=4); bind their checksums/expected plaintext outside timing. Each paired observation measures both lengths for both flavors, balanced order; use `(long − short)/additional plaintext GB` for decoder wall and child CPU. This estimates marginal steady concat cost incl. event transport, not single-frame latency; record raw totals, bound/inspect attach jitter, reject negative or unresolved slopes as an inconclusive calibration, never drop individual pairs to rescue a pass. Alternatively bracket the exact operation with identical outer wall/process-CPU clocks in separate calibration exports of **all three** builds, after readiness and before profiler shutdown; save the calibration delta. Do not compare Tracy-zone time with clean process wall as an overhead estimate.

Proposed budgets, not measured: in both series require the 95% paired median interval for incremental wall **and** decoder CPU change vs OFF within ±3% disconnected, ±10% connected; OFF/OFF within ±3%. Report startup/attach/shutdown separately. If clocks, host noise, coverage or budgets fail, label that configuration **qualitative only** (topology/counts); thin probes or move to a coarser measured replay before making quantitative attributions. Do not subtract a profiler tax or use a pass at W=1 to certify W=8, a different sink, target or corpus. Even passing this whole-operation gate doesn't establish negligible *per-zone* bias for tiny stages.

**Portable/native is a separate axis.** Build portable Rust (empty extra rustflags, default runtime-dispatched merge) and, when justified by clean data, same revision/features in a separate `-C target-cpu=native` target. Compare Rust to itself first, then each to stock native C. If useful, separate C `ZXC_NATIVE_ARCH=OFF` **with the same multiversion dispatch** from an explicitly no-intrinsics diagnostic; neither means “same ISA as portable Rust”. The replay independently saw AVX2 in both the C block and Rust merge. Native Rust does not acquire C's padded-output proof, tables, token specialization, writer thread or worker-local pread. Native closing a gap argues for compiler/dispatch follow-up; a residual warrants a section replay with byte-exact symbol outputs and clean cycles/symbol. Neither finding by itself justifies porting C's fast loops or weakening checks. Keep toolchain experiments outside this patch series.

## Bounded acceptance for Sol high

1. Return the local fork path/base/tip/tree, zxc-rs-owned patch series + lock/recipe/map, and evidence of reproducing the tree from the pin. Demonstrate OFF works with no Tracy checkout/C++, and ON links one client and covers every compiled decompressor variant. Keep the ordinary Rust smoke usable; Rust changes limited to the missing cfg-gated sites/map. No release tuning, oracle changes, publication or broad refactor.
2. After exclusive access is available, return one exact attached C/Rust **pair on `sao` W=1** and one on **`single` W=8**, plus exact OFF/detached controls, failure/timeout and wrong-version behavior, and corruption control. Export, check all six physical ID counts, derive preparation from intervals, and summarize one row per implementation/case with trace/CSV hashes. Demonstrate clean release has no Tracy. No full worker sweep or new timing verdict required in this implementation slice.
3. Ship the overhead protocol/runner and label traces **uncalibrated** unless the per-cell gate actually ran and passed. A short smoke is enough to accept tooling, never enough to promote timing claims. On a pin/protocol/semantic change, fork a new base/series in isolation, review a range-diff and call-site/ISA/error-path audit, regenerate the map (bump major on changed boundaries), rerun exact counts, negative cases and calibration. Keep prior recipes addressable. Add a zone only for a named decision unresolved by these data, with a new boundary/census and overhead budget. If the patches cease to answer such a question, freeze them at their pin rather than maintain a parallel codec.
