# Put regular-file body reads on the decode workers

**Trial:** Can the caller supply eight workers faster by reading only the next eight-byte block header, then handing its file position and a recyclable buffer to one worker? Keep 16 credits from admission through write. The requested bar is a reduction from roughly 25 ms to 22.5 ms or better on a 25 ms run; the reported ~21 ms C timing is context, not the control. A pass concerns W8 end-to-end wall on two particular warm files. It would not explain single-worker decode cost.

The [W4 wait traces](../../doc/profiling/decode-waits.md) found 2.02–2.12 ms of interior empty-queue wait overlapping `next` on `mozilla.c7`, versus 0.29–0.38 ms exposed behind the head. Moving reads outside the pool into a preloaded cursor helped some pool intervals but hurt the whole CLI. Neither observation predicts a W8 saving. The [shipped pool](../../doc/profiling/decode-pool.md) already saved 41–42% concat wall, without a single-frame win. Keep it, the retained [Huffman setup](../../doc/profiling/decode-next0.sol.md), and output buffering fixed. This wave selects the [positioned alternative](design0.astra.md#if-the-session-is-not-the-answer) for one isolated trial.

## Select a source once, before type erasure

Build in a scratch export of `3f711434` (or record a newer clean pin). Give only that trial CLI a mode, e.g. `ZXC_TRIAL_INPUT=stream|positioned`, default `stream`. `positioned` requests the file optimization **when eligible**. No production environment switch. At [CLI `decode`/`input`](../../crates/cli/src/main.rs) leave `-` on locked stdin even when redirected. For a named input open once; inspect the **open handle**, not `path.metadata()` followed by reopen. Use positioned reads only on Unix, regular file with meaningful positive length, Crossbeam, workers >1 and explicit stable-file opt-in. Unknown length/capability, named FIFO, special file, serial or other backend: hand the very same newly opened file to the usual buffered `Read` path. Keep dictionary loading, config validation, `test`, writer ownership and `output`'s flush/no-clobber transaction. Never reopen a FIFO to fall back. After consuming input or producing output, failure is terminal; no stream restart. Opt-in asserts ordinary stable storage; `is_file()` alone cannot certify that or exclude every virtual file.

Keep `zxc_parallel::decode(impl Read, impl Write, ...)` intact (no downcast, `Seek`, `Send` or `'static` bound on the caller). Add a scratch file-specific entry, e.g. `decode_file(File, w, options, config)` for trial selection, with `config.validate()` before any dispatch. At [seek `ReadAt for File`/`FileSource`](../../crates/seek/src/lib.rs) the Unix primitive is just `FileExt::read_exact_at`. Use that directly on one borrowed `&File` shared with scoped workers. No new shipping dependency: `FileSource::open` would reopen and cache length, its portable implementation serializes seek/read, and `Archive` requires an index and serves a different validation contract. Do not clone file cursors and `seek`, mmap, preload, scan ahead, or materialize a list of blocks.

## One framing loop, two job constructors

In [parallel `decode_channel`](../../crates/parallel/src/lib.rs), factor **only** the input-dependent closures out of the equal-block-size epoch loop in the trial tree. A private monomorphized helper takes `r: R: Read`, `next(&mut R, FrameHeader, &mut Vec<u8>) -> Result<Option<J>>`, and a `Sync` worker materializer `(J, Vec<u8>) -> Result<(DataBlockHeader, Vec<u8>)>`; wrap `J` with the existing dictionary slot. Stream instantiation: `read_data_block` + identity. Positioned instantiation: logical cursor + descriptor below. Workers capture immutable file/initial length separately from the mutable caller cursor. No runtime enum per generic block. Keep one copy of `DecodeFrame::start/commit/finish`, dictionary lookup, `BlockDecoder::decode_owned` and the size-change join. No changes to `channel.rs` dispatch/credits are required.

1. Cursor fields: `file`, `pos: u64`, `end = initial fstat.len()`. Implement `Read` by reading at `pos` exactly `min(dst.len(), end-pos)` initialized bytes, then advancing on success; zero at the logical end. Short physical read before `end` is an error. No `BufReader` on this cursor: read only requested metadata, with no prefetched body to discard or miscount. At final logical EOF confirm current length and modification stamp against the opening metadata on the *same fd* before success (use Unix mtime/ctime incl. ns; ignore atime). This catches many in-place changes including append past captured EOF; it does not lock the inode. Use checked conversions/additions for every range.
2. [Codec `read_data_block` and `DecodeFrame`](../../crates/codec/src/frame.rs) already implement all stream semantics. Extract its small header classifier into a helper taking raw `[u8; BLOCK_HEADER_SIZE]` and frame settings, returning `Option<DataBlockHeader>`: kind 255 must pass `validate_eof_header`, otherwise `DataBlockHeader::parse`. Use this helper in both admissions; retain stream body read/resize untouched. Positioned `next`: remember header offset `h`, read the eight bytes, classify; on EOF stop immediately with cursor just after those eight bytes. For data, `body_start=h+8`, `stop=body_start+header.body_size()` checked, require `stop<=end` else `UnexpectedEof`, advance cursor to `stop` with no body read. Descriptor `(frame settings, raw header, h, stop)` plus slot; channel attaches the frame-local sequence number. No generation counter needed: `session.run` drains and commits before footer; no descriptor outlives that frame on success, no pool reuse after failure.
3. Worker reads **at h** into a local `[u8;8]`, compares all bytes to descriptor, reparses using the job's settings and [wire checks](../../crates/codec/src/wire.rs); reject EOF/other kinds, overflow, mismatch or recomputed end different from `stop` or beyond captured `end`. Only then `buf.resize(parsed.body_size(), 0)` and `read_exact_at` from `h+8`, checksum trailer included. Exact read detects physical shortness even after admission. Two worker reads intentionally avoid a whole-body shift/copy for header stripping. Call the existing [owned decoder](../../crates/codec/src/block.rs) with this header, exact-length buffer, resolved dictionary and **per-frame** index; commit only its verified span/checksum. This is not a snapshot: header comparison and final stat cannot prove body immutability between reads, especially for coherent same-length checksumless rewrites. Require stable length/content for the operation; never promise authenticity or atomic plaintext delivery to a stream.
4. Caller keeps one cumulative output total across frames. `commit` checks max output before write and records disk size, actual plaintext length and verified checksum; the footer is built from those records. `finish` reads and checks the seek header and consumes exactly the computed table extent when indexed (stream parity, **not** an entry-by-entry index audit); footer widths/digest depend on committed state, not descriptor predictions. Only after successful finish call `start(false)`; preserve empty frames, final vs initial EOF, partial magic and trailing-data rejection. Resolve dictionary even for empty frames; first matching ID including zero wins. Same-size frames may switch flags/dictionary and reset block index; changed block limit drops scratch and slots even across an empty frame.

### Memory and failure order

The existing [channel `Session::run_observed`](../../crates/parallel/src/channel.rs) lends `free.last_mut()` to `next`, pops it only on data, sends `(index,(job,buf))`. A descriptor therefore **moves the existing credit Vec** into the worker; no second input pool or body upload on the channel. A worker may allocate only after wire size checks (block limit ≤2 MiB, plus ≤4 trailer bytes). RAW returns that backing Vec with logical plaintext length; compressed decode swaps with worker output. Keep the decoder's per-worker section/output scratch, K migrating buffers and O(K) small descriptors/results; no O(block count) production state or per-frame accumulation of retained capacities. A Vec capacity can exceed requested size; report capacities separately from logical bytes/RSS if measuring memory. Empty/EOF reservation does not consume a credit.

Input/header errors terminate admission after earlier admitted indices; worker read/validation errors are ordinary results at that index. Result receipt never releases credit. Pending results wait behind the head; only contiguous successful commits return buffers. Earlier block or writer error still wins over later worker or cursor error. Never read another frame after a failed footer. Leave cancellation, panic conversion, disconnect/drop and join in the existing scope. Earlier output to stdout on a late error is allowed; an explicitly named destination must not be published on failure.

## Sol handoff: evidence in order

**1. Prove selection and parity first.** Compare independent parent A, trial forced stream S and trial positioned B on the *same* named fixtures; separately show via an untimed read/syscall trace or test hook which path ran. Check W1 and non-Crossbeam, actual pipe (`cat archive | cli decode ... -`), named FIFO and nonregular fallback, not just a `Cursor` or `<archive`. Bound FIFO tests by timeout. Exercise existing blocked-head, EOF-credit, epoch, panic/join, limit and first-error tests. Run locked Release nextest for workspace, transports enabled and no-default-features paths (explicitly test codec without defaults). Add differential cases:

| Case | Required observation |
| --- | --- |
| RAW/SPL/PAK; checked and unchecked; indexed and ordinary; empty between nonempty, mixed sizes/flags, dictionary changes incl. ID zero/missing on empty | Same bytes and length through physical EOF; same success/error kind and committed prefix on stable inputs. Use K=1, K<W, W8/K16. |
| Empty input, partial prologue/trailing garbage, malformed/oversized block, EOF fields, truncated header/body/trailer, bad intermediate checksum, seek header/extent or footer/digest (including nonfinal frame) | Reject; no later-frame output. Check cumulative limit exactly at/one below boundary, earlier writer error vs later corrupt head/source. |
| Controlled admission → worker read, without timing races | Pause via test hook after descriptor capture; substitute another *valid* header of same extent, truncate within body, append at final EOF. Require mismatch/short read/final stability error respectively. Unit-test near-u64 overflow without huge allocation. |
| Real CLI destination, fresh path `-o OUT`, and existing sentinel destination | `cmp` plaintext on success; existing file untouched; no published partial output after later error. Check stdout SHA-256 and byte length separately, zero exit and quiet stderr for valid cases. |

**2. Establish whether reader work fell.** In separate diagnostic A/B builds, count caller vs worker header/body bytes and jobs, then measure coordinator **thread CPU** and elapsed time summed around successful data `next` calls (Linux `CLOCK_THREAD_CPUTIME_ID` + monotonic; same edges in both). Report per decode and per block, frame tails/EOF separately, for both layouts. Batch per-thread counters locally; emit only after flush, check job counts and plaintext identity. Paired warmed repetitions with both diagnostic modes and a capture-vs-clean noise check. Require repeated lower reader CPU beyond probe noise, not merely zero caller payload bytes by construction. Worker syscalls, initialized resize, cache locality and readahead can easily consume the saving. Optional discriminator if reader result ambiguous: port the [wait reducer's interior definition](../../doc/profiling/decode-waits.md#what-the-reducer-counts) per frame to the persistent pool. Exclude startup and post-last-send drain; intersect empty-queue job receive with caller `next` while further blocks remain, report wall union and worker-ms. Time worker pread separately from decode; a worker waiting for I/O is not a worker starved for a job. Do not use off-CPU wall or queue depth alone as proof. Diagnostic binaries never supply the clean gate.

**3. Clean paired decision.** Reuse the [manifest](../../doc/profiling/decode-pool-data/fixture-manifest.json), prepared `single.zxc` and `concat.zxc` plus `plain` (the long single was separately encoded by C7; preserve each archive exactly). Adapt the [pool bench](../../doc/profiling/decode-pool-data/bench.py) with explicit commands/env, pipe feeder and fresh A/A at each setting; archive the adapter and invocation. From separate clean exports build `CARGO_ENCODED_RUSTFLAGS='' cargo build --release --locked -p zxc-cli`, same toolchain/default portable features, no ledger, Tracy or probe. Hash binaries, sources/patches and fixtures. Before timing, stream each mode's full output through length and SHA checks, including pipe and real output, and require checksum rejection. Record commands and verify selection on untimed equivalents.

Primary comparison A vs B: `decode --backend crossbeam --threads 8 --slots 16 FILE` to `/dev/null` with warm page cache. Same-binary S vs B isolates the mode on identical input; check A vs S if generic refactor shifts results. To test pipe regression, compare A vs B-requested on identical actual pipe feeds. Use separate feeder process from same warm file, fixed affinity and pipe size, verify both exits; measure launch-to-decoder-wait wall consistently, decoder user+sys via its own `wait4`, never charge feeder CPU as decoder CPU. Record feeder CPU separately. A named file attached to fd 0 is not this control. Time real-file writes in separate confirmation pairs on same FS, fresh output names with unlink/hash outside timed interval, report buffer flush vs fsync distinction. W1 is a selection control, C a separate reference.

Hold `.test-agent/zxc-perf.lock` across verification/warmups/runs. Pin W8+caller to same eight physical cores; record mask, siblings/reservation, load by series and governor/boost. Two independently seeded shuffled series, each 24 adjacent balanced AB/BA pairs **per layout/contrast** with interleaved fresh A/A, discarded warmups. Record raw order, wall ns, user/sys and decimal CPU-s/GB plaintext, status, stderr, builds, settings and seeds. Report per-series median paired percent change and order-statistic intervals as in [the ranked rule](next0.sol.md#paired-decision-rule); A/A is noise, not a subtraction. No pooling series or trading single for concat. Pass only if both series on **each** file resolve ≥10% lower wall and ≤3% higher child CPU/GB, with exact output, reader CPU or interior starvation demonstrably reduced and no pipe fallback regression. For the fallback predeclare +3% upper tolerance on wall and CPU, flag any repeatable slowdown even within it; wide intervals are not evidence of equivalence. If noise/interval crosses a decision boundary, call unresolved; at most one quieter repeat. Publish timings, diagnostic counts, tests and trial diff including misses. On miss/unresolved keep only reproducible evidence/scratch patch; no production selector, broader scheduler redesign or follow-on tuning in this trial. On pass review stable-file opt-in and platform coverage before changing any default.
