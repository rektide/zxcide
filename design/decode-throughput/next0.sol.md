# Next decode throughput trials

**Start with one SPL16 copy change. Nothing needs reverting.** The rejected two-group AVX2 merge used 12.5% more long-literal cycles and 6.5% more checked-block cycles. In the working tree at handoff, `merge.rs` and `flat.rs` matched the trial parent `3ce5ff5b`, and the only codec diff from that pin was the retained [bitmap differential test](../../crates/codec/src/entropy/tests.rs). The candidate remains scratch/evidence only. Keep the one-group merge and the three-bit unpack (`845a76c6`: −8.1% long literals, −4.4% checked-block cycles, CLI unresolved).

## Ranked options

1. **SPL16: shrink the copy for short, nonoverlapping match extensions.** In [`reconstruct`](../../crates/codec/src/block.rs), try one fixed 32-byte snapshot/store for **20–32 byte** matches already eligible for the one-byte SPL16 extension path; keep the current 33–64 byte copy, two-inline-token batch and all generic fallbacks. The hypothesis is less copy work without an out-of-line move; the extra split must pay for itself. Keep the existing guards in the first trial, including the initialized output-room check; snapshot before the match store because physical slack can overlap even when logical history does not. Commit only the logical match bytes and consume the extension only on success. Reconstruction was about half the older portable checked-long samples, not half the Rust–C gap. The prior census found 254,528 / 345,106 extensions of **20–64** on C7 `mozilla` / `webster`; it does not count this narrower eligible class. Do one eligibility count on the fixed bytes and inspect candidate codegen; stop early if coverage is sparse or the copy still lowers to a move call. Use checked `single` as primary, `mozilla` as a coverage control, `sao` (zero extended matches) and an existing small-block/fallback fixture as regression controls. Run the [bytewise reconstruction tests](../../crates/codec/src/block/tests.rs) plus 20/32/33/64 boundaries, short buffers, real overlap, dictionary crossing and truncated extensions. Gate CLI work on ≥5% fewer checked `single` cycles/byte with both replay intervals below zero, instructions and thread CPU as cross-checks, and no repeatable control regression. Then require ≥5% `single` W8 throughput improvement in both CLI series for an end-to-end claim, with W1 and `sao` as controls. Miss the replay gate: drop this copy split, don't widen the batch or tune a ladder of lengths.
2. **Regular-file input: send positions instead of bodies.** If the priority is W8 wall time, try the [positioned-input design](design0.astra.md#if-the-session-is-not-the-answer) on stable regular files before erasing `File` to `Read`. Compare with caller reads on the *same file*, keeping the shipped pool, `K=16`, ordered commit and footer barrier fixed. Revalidate header/extent in the worker; keep the generic pipe path. Test `single` and concat, plus an actual pipe fallback and a real output file. Require repeatable ≥10% lower W8 wall on both fixed inputs, ≤3% higher child CPU/GB, and no fallback regression; check that reader work or interior starvation falls. Stop if the clean gain is absent; pool reuse already saved 41–42% concat wall without a single-frame win. Don't bundle a new writer or wider queue.
3. **Huffman setup: remove the comparison sort, not the tree.** In [`Tree::new`](../../crates/codec/src/entropy.rs), trial counting/bucketing the 256 symbols by depths 1–11, preserving ascending symbol order within each depth, the Kraft checks and the single-symbol case. Older token samples put 16.9% in `Tree::new` self, before sort attribution; this is a token-side hypothesis, not a full-block forecast. Require exact sections and invalid-table rejection; use original long tokens for the first cycles/instructions signal, literals and `sao` as controls. Drop it if there is no repeatable section saving or it fails to carry through to checked blocks.
4. **SPL16 true overlap: test distance one as a fill.** Separately from #1, after the dictionary case, try an exact-length fill from the preceding byte when distance is one and the match is in already-produced output, rather than repeatedly doubling the copied pattern. Keep all other distances, extended-length validation and block budget unchanged. Do one eligibility count on `single` and `sao`; don't build it if this class is rare. Require bytewise-oracle coverage of dictionary-to-output crossing, tiny blocks and long fills, then the same checked-block gate as #1; stop rather than add more distance cases on a miss.
5. **Defer mixed merge.** Reopen only for a different mechanism that removes work, for example a bounded one-group load/store arrangement that avoids stack lane assembly in the portable binary. Do not retry pairing groups or alternating scratch layouts just because merge led the old literal profile. Require fewer long-literal instructions **and** cycles, a checked-block win before CLI, and no skewed/short, `sao` or scalar loss. Keep the exact-end mask-pair test; no relaxed bounds or wire padding.

## Paired decision rule

Use the existing [checked replay](../../doc/profiling/decode-replay-data/perf.py), [CLI harness](../../doc/profiling/decode-pool-data/bench.py) and [fixture manifest](../../doc/profiling/decode-pool-data/fixture-manifest.json). Compare clean locked portable Release builds of a fresh Rust parent and one candidate (no Tracy or ledger); pinned C is a separate reference, not A. Verify exact bytes/length through EOF and checksum rejection before timing, with existing replay fingerprints during timing; also check the no-default-features path. Under `.test-agent/zxc-perf.lock`, run two independently shuffled series of 24 adjacent balanced AB/BA pairs with fresh interleaved **A/A** pairs at the same settings. Warm first, pin replay to one core and W8 to a fixed physical-core mask, record unreserved SMT siblings, load and clock policy, build/fixture hashes and raw order. Report per-series paired medians and intervals (replay cycles/instructions per plaintext byte or decoded symbol; CLI wall and child CPU/GB). Reject multiplexed replay counts. A/A measures noise, not a correction to subtract; if noise or intervals straddle the decision threshold, call it unresolved, not a gain or proof of equivalence. One quieter repeat at most before moving on. No fresh timings or codec changes were made for this handoff.
