# Rust and upstream C codec pipelines at the performance pin

**Prioritize decode of existing SPL archives, not a wholesale C encoder port.** On the corrected two-file run Rust Dense already encodes faster and slightly smaller than C7 in aggregate. But both decoders take longest on the Rust Dense archives, and on Dense `sao` the Rust decoder also spends considerably more child CPU than C. Pursue two separate goals: make those *same bytes* cheaper to decode, then decide whether new Dense archives should charge for decode work instead of optimizing compressed size alone. Rust need not match C's parse decisions or thread topology to reach performance parity.

### What the decoders actually process

An untimed header census regenerated all six archives with the saved binaries and checked binary, plaintext and archive SHA-256 against `raw.json`. All data blocks were SPL16. Counts below sum only inline-Huffman sections; all other sections in these archives were raw.

| `sao` / Split | 0 / 14 | 0 | 0 / 14 | 393,598 |

To reproduce, execute the six `kind == "encode"` jobs from `raw.json` with the recorded binary and plaintext, capture stdout, and require the recorded archive hash. Walk data records from byte 16 to the type-255 marker; the 8-byte header holds kind at byte 0 and LE32 payload size at byte 3. Advance by `8 + payload_size + 4` (checksums present in these fixtures). For each SPL body read LE `<IIBBBB` at its start: sequence count, literal count, literal encoding, token encoding, reserved lane and offset mode. Sum literal count only at literal mode 2; sum all sequence counts. This is an archive-description probe, not a replacement for the decoders or their verification.

Dense `sao` sends **2.32×** as many literal bytes through Huffman as C7, with nearly the same sequence count. That makes entropy policy and Huffman decode attractive independent targets; header counts cannot tell how many merge levels or LZ fallbacks occur. Dense `dickens` instead trades fewer Huffman literals for **19% more** LZ sequences, supporting a separate LZ-centric control. Neither comparison assigns the wall delta to one stage.

## Encode: match search → priced parse → wire sections

1. **History and candidate search.** Rust Packed and Split share the [single-slot hash parser](https://github.com/rektide/zxcide/blob/f76005b0950e81516c54cceffdefb1f26a543921/crates/codec/src/encode.rs#L47-L116), not C's per-level policies. Dense [`Parser::insert`/`longest`](https://github.com/rektide/zxcide/blob/f76005b0950e81516c54cceffdefb1f26a543921/crates/codec/src/encode/dense_match.rs#L6-L105) resets 17-bit five-byte hash heads, keeps a 64 Ki-entry predecessor-delta ring, walks at most 24 candidates in a 64 KiB history window and extends via scalar 64-bit XOR/ctz then a byte tail. Sufficient length is 128. C [`zxc_lz77_find_best_match`](https://github.com/hellobertrand/zxc/blob/5719a96f778226868b29dba621a8c4e302b74d7c/src/lib/zxc_compress.c#L584-L860) uses tagged, epoch-marked heads with a delta chain and a repeat-offset probe. [Level parameters](https://github.com/hellobertrand/zxc/blob/5719a96f778226868b29dba621a8c4e302b74d7c/src/lib/zxc_internal.h#L1234-L1250) give level 7 depth 128 and sufficient length 256; levels 3–5 use lazy SPL and can split some long matches to avoid slow length escapes, levels 1–2 use PAK. Epochs avoid a full head reset on each block; they do **not** license matches into another block. With a dictionary, Rust copies prefix and plaintext into history per block (cheap modes can reuse a hash snapshot); C worker copies the prefix once into its local dictionary buffer and copies each new plaintext after it. See the [dictionary encode study](dictionary-encode.md); no dictionary cost is measured in the two-file run.
2. **Price and backtrack.** Rust [`parse`/`parse_span`](https://github.com/rektide/zxcide/blob/f76005b0950e81516c54cceffdefb1f26a543921/crates/codec/src/encode/dense_match.rs#L107-L235) uses bounded 32 KiB AoS state windows (~896 KiB including heads/links), seven bits per literal, 21 per sequence plus literal/match escape prices. It tracks literal-run length on the winning path only. It considers shorter endpoints at the same offset, skips most long-match interior searches but still inserts history keys, and can extend a chosen match across a span boundary. It backtracks to a `Vec<Match>` and reverses each span's chosen actions. C [`zxc_lz77_optimal_parse_spl`](https://github.com/hellobertrand/zxc/blob/5719a96f778226868b29dba621a8c4e302b74d7c/src/lib/zxc_compress.c#L1046-L1361) samples a block literal price, uses a 24-bit base sequence price plus match escapes, with no corresponding literal-run escape in the DP. Its full-block SoA arrays consume ~4 MiB at 512 KiB (before heads/links and other scratch); same-price length ranges use [vectorized compare/update where available](https://github.com/hellobertrand/zxc/blob/5719a96f778226868b29dba621a8c4e302b74d7c/src/lib/zxc_compress.c#L870-L1026), with higher overflow costs scalar and covered transitions pruned. It backtracks into an endpoint bitmap and emits token/offset/extra and literal scratch streams in one forward walk. Both are approximations, not an optimum over all offsets or resulting entropy tables. C's stronger search can cost more, and Rust's smaller state may improve working-set locality; the clean timings do not price either effect.
3. **Select entropy and emit.** Rust [`BlockEncoder::block`](https://github.com/rektide/zxcide/blob/f76005b0950e81516c54cceffdefb1f26a543921/crates/codec/src/encode.rs#L198-L285) traverses matches to write literals, tokens, offset lane and escape lengths into a raw candidate. Dense [`best`/`Tree::emit`](https://github.com/rektide/zxcide/blob/f76005b0950e81516c54cceffdefb1f26a543921/crates/codec/src/entropy/pack.rs#L110-L277) selects by actual byte savings against a descriptor-adjusted budget, using RLE for literals and inline or dictionary Huffman for eligible sections (tokens RAW or inline Huffman). It uses bounded lengths (a fast tree and package-merge fallback), exact run sizing before emission, and allocated winning candidate bytes; if any section changes it reassembles the block in a second Vec, copying the unchanged suffix too. C [`zxc_encode_block_spl`](https://github.com/hellobertrand/zxc/blob/5719a96f778226868b29dba621a8c4e302b74d7c/src/lib/zxc_compress.c#L1582-L2070) prices RLE using vector-capable run discovery, estimates Huffman from histograms, adds a per-level decode tax, and emits winners into the final slot. [`zxc_huf_build_code_lengths` and `zxc_huf_nudge_code_lengths`](https://github.com/hellobertrand/zxc/blob/5719a96f778226868b29dba621a8c4e302b74d7c/src/lib/zxc_huffman.c#L163-L302) use length-limited package-merge and a separate [decode-cost-aware adjustment](https://github.com/hellobertrand/zxc/blob/5719a96f778226868b29dba621a8c4e302b74d7c/src/lib/zxc_huffman.c#L778-L944). C aliases parser and Huffman-build scratch at different lifetimes; it can still repeat tree/layout work between pricing and emission. These differences matter more than copying the C depth limit alone: fewer bytes can mean **more** partitions to decode.
4. **Layout and commit.** SPL uses a general header with literal/token counts and modes, size descriptors for coded sections, then literals, nibble tokens, byte or LE16 biased offsets, and length extras. PAK carries raw literals and fixed four-byte sequence records; no entropy descriptors. Both leave at least 32 bytes beyond the literal section for a compressed block, using trailing sections before adding slack, and can fall back to RAW if the compressed result is not worthwhile. Rust hashes `plain` after selection and writes header/payload/trailer separately; C [`zxc_compress_chunk_wrapper`](https://github.com/hellobertrand/zxc/blob/5719a96f778226868b29dba621a8c4e302b74d7c/src/lib/zxc_compress.c#L2395-L2426) writes a complete physical data block in the slot. Parity here means avoiding avoidable streams/copies, not replacing Rust's free RAW buffer transfer with C's output copy.

## Decode: sections → reconstruction → verified output

1. **Section limits and preparation.** Rust [`unpack`/`section`](https://github.com/rektide/zxcide/blob/f76005b0950e81516c54cceffdefb1f26a543921/crates/codec/src/block.rs#L112-L234) bounds plaintext counts (`literal + 5 × sequence ≤ block limit`) before allocating, validates representation and slices descriptors/literals/tokens/offsets once. Raw sections borrow exact slices; RLE and Huffman return owned vectors. The reusable output Vec starts at the known minimum and grows geometrically for matches without preinitializing a full frame-limit block on every call. C [`zxc_decode_block_spl_impl`](https://github.com/hellobertrand/zxc/blob/5719a96f778226868b29dba621a8c4e302b74d7c/src/lib/zxc_decompress.c#L722-L961) specializes raw/entropy and dictionary variants, validates section bounds and decodes coded sections into [lazy worker-local scratch](https://github.com/hellobertrand/zxc/blob/5719a96f778226868b29dba621a8c4e302b74d7c/src/lib/zxc_common.c#L353-L399); raw sections point into the body. C RAW block path copies to destination; Rust [`BlockDecoder::decode`](https://github.com/rektide/zxcide/blob/f76005b0950e81516c54cceffdefb1f26a543921/crates/codec/src/block.rs#L46-L87) exposes a verified slice into the input instead.
2. **PivCo decode.** Both validate and interpret canonical lengths, visit runs in wire order, derive child populations via popcount (masking unused bits), and produce symbols from flat subtrees or merge siblings bottom-up. Rust [`Tree::new`/`decode`](https://github.com/rektide/zxcide/blob/f76005b0950e81516c54cceffdefb1f26a543921/crates/codec/src/entropy.rs#L30-L185) builds heap nodes/lookup tables for inline tables, records runs with a breadth-first queue, allocates and zeroes two count-sized vectors, and copies mixed merges back into their original intervals (zero-sided runs skip merge). For a mixed node with `n` symbols the gather writes `n` and the return copies `n`, not counting child reads or initialization. [`merge::gather`](https://github.com/rektide/zxcide/blob/f76005b0950e81516c54cceffdefb1f26a543921/crates/codec/src/entropy/merge.rs#L76-L135) uses portable runtime-dispatched SIMD shuffle plus bounded scalar paths; [flat unpack](https://github.com/rektide/zxcide/blob/f76005b0950e81516c54cceffdefb1f26a543921/crates/codec/src/entropy/flat.rs#L1-L31) is fixed-width scalar unpack/grouping. C [`zxc_pivco_tree_build`](https://github.com/hellobertrand/zxc/blob/5719a96f778226868b29dba621a8c4e302b74d7c/src/lib/zxc_huffman.c#L1048-L1133) builds dense level tables, and [`zxc_pivco_decode_core`](https://github.com/hellobertrand/zxc/blob/5719a96f778226868b29dba621a8c4e302b74d7c/src/lib/zxc_huffman.c#L2176-L2281) stores counts and per-level run starts in fixed arrays, alternates scratch/destination by depth and ends in destination without per-node copy-back. Its [merge and flat kernels](https://github.com/hellobertrand/zxc/blob/5719a96f778226868b29dba621a8c4e302b74d7c/src/lib/zxc_huffman.c#L1391-L1677) have CPU-specific paths. Less copy-back need not imply faster decode: the earlier [Rust layout trial](pivco-scratch.md) cut traffic but failed serial and component gates, and was not a port of C's dense level tables. Preserve Rust's exact run exhaustion and missing-child rejection; the C core bounds every run but does not require exact exhaustion at the end of that routine.
3. **LZ reconstruction.** Rust picks PAK/SPL8/SPL16 before the loop. [`Spl16::batch`/`reconstruct`](https://github.com/rektide/zxcide/blob/f76005b0950e81516c54cceffdefb1f26a543921/crates/codec/src/block.rs#L274-L429) amortize bounds over two inline, logically non-overlapping tokens with 16-byte literal and 24-byte match stores; keep the first token when the second falls back. The generic loop handles extras, larger copies, dictionary crossings and real overlap (doubling via initialized history). It tracks remaining match budget and never commits store slack as plaintext. C [SPL fast/terminal loops](https://github.com/hellobertrand/zxc/blob/5719a96f778226868b29dba621a8c4e302b74d7c/src/lib/zxc_decompress.c#L962-L1178) split bulk work by token and output conditions; [PAK has its own loops](https://github.com/hellobertrand/zxc/blob/5719a96f778226868b29dba621a8c4e302b74d7c/src/lib/zxc_decompress.c#L1183-L1419). The padded bulk contract permits fixed-width/wild copies and [distance-specific SIMD overlap or fill kernels](https://github.com/hellobertrand/zxc/blob/5719a96f778226868b29dba621a8c4e302b74d7c/src/lib/zxc_decompress.c#L143-L516), with an exact tail and safe variants for entry points without the same pad contract. C [dispatch](https://github.com/hellobertrand/zxc/blob/5719a96f778226868b29dba621a8c4e302b74d7c/src/lib/zxc_dispatch.c#L225-L385) selects whole kernels (AVX2 expected for this host/build, not independently profiled here); Rust's fixed copies can lower to vector moves, but its matcher and overlap loops are not equivalent ISA-specialized kernels. Do not import a wild-copy loop unless Rust owns and proves both readable initialized source and writable tail capacity, past-history bounds and logical length independently. Model offset as wire value + 1; match sources may consume the dictionary suffix and then already produced output, never unproduced bytes.
4. **Verify and publish.** Rust and [`zxc_decompress_chunk_wrapper_body`](https://github.com/hellobertrand/zxc/blob/5719a96f778226868b29dba621a8c4e302b74d7c/src/lib/zxc_decompress.c#L1598-L1655) hash reconstructed logical bytes, not overstore slack; checksummed pipeline output is handed to the ordered writer only after block verification. Rust validates expected plaintext length when the positioned caller provides it. Treat malformed count/mode/extent, truncated or invalid extras, history underflow, checksum failure, seek/footer truncation, and max-output failure as independent checks; interop acceptance on valid archives does not require identical error codes or identical permissiveness on malformed bytes. Check the exact terminal path, not just the padded worker path.

## Experiments in priority order

The [four-worker wait traces](decode-waits.md) point to the coordinator's input step on `mozilla`: during 2.02–2.19 ms per frame it was preparing the next block while workers waited on an empty queue. The corresponding exposure to ordered delivery was 0.29–0.46 ms. Keep eight slots and measure how much input-step time is spent running versus descheduled before changing the reader. The [traversal queue trial](pivco-queue.md) also missed its elapsed-time target despite removing 99.6% of queue growth and allocation events on its primary workload.

**Follow-up decisions:** [Short match extensions](dense-decode.md#follow-up-short-match-length-extensions) and [worker-owned Huffman byte buffers](pivco-worker.md) shipped. The [literal savings sweep](dense-literal-savings.sol.md) retained the existing Dense policy: at 4%, `sao` took 44% less serial time in Rust and 21% less in C, but nine files had identical archives and neither decoder met the 5% full-corpus wall-time goal. The rows below preserve the original hypotheses and measurement criteria.

These are proposed gates and expected directions, not measured speedup forecasts. For byte-preserving changes, benchmark fixed hash-checked C7, Dense and Split archives, not archives produced by each candidate; add C3, PAK and RAW controls. Compare block-only decode/encode, checksum cost and full CLI separately, with paired shuffled runs and child CPU as well as wall. Run counters on separate invocations from timing. Sample instructions, cycles, branches/misses and L1D/LLC misses per plaintext byte, plus the stage counters below; total CPU is not an attribution counter. Use full Silesia before promoting, plus 4 KiB, incompressible, long runs, dictionary crossings, scalar/no-SIMD and component controls. Proposed screen for a default speed optimization: repeatable ≥5% improvement on its named hot workload, no unexplained >3% regression on a control, and interop, exact plaintext/EOF plus existing malformed-input and bounded-output tests green.

Do not start by fusing entropy with LZ: both pipelines materialize sections for a reason (PivCo discovers run counts and decodes bottom-up, while LZ needs forward token/literal cursors and history). First remove demonstrably redundant allocations, writes or checks at proven boundaries. The ordinary serial decoder, portable builds and verified-output contract are baselines to retain, not incidental costs that a parity experiment may drop.
